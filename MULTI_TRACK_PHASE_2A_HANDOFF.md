# Multi-Track Phase 2A — Handoff

Phase 2A adds the representation and loading layer for Multi-Track. A
schema-2 profile now carries a Sweep's own sections once, plus `TRACKS` (1–3
résumés). `config` loads it without overlaying any track, and `scraper` builds
one immutable `TrackContext` per track.

- Each track is built from config's pristine defaults and its own values, and
  carries its own Phase-1 `ScoringContext` and its own explicit engine.
- No track plans, filters, scores or ranks anything yet.
- A schema-2 profile that reaches one-profile code fails closed; it never runs
  as one of its tracks.
- Schema 1 is unchanged.

Nothing is committed, pushed or deployed. No provider or model was called.

## C. Exact Schema-2 Representation

Written only by `render_sweep(name, tracks, prefs)`. `tracks` is `[{"id", "engine", "derived"}]` in the user's order. A 3-track example, with values shortened:

```python
"""<name> — a Multi-Track Sweep generated by auto-apply/make_profile.py.  (no résumé prose)"""

PROFILE_SCHEMA = {"version": 2, "engine": 'multi'}

LOCATION_HINTS = [...]            # when the preferences set any: Sweep, as render() writes it
SITES = {...}                     # when Configure set any: Sweep, as render() writes it

SEARCH = {"locations": [...], "salary_min": None, ["max_results": n]}
SETTINGS = {"min_comp_usd": ..., [max_spend_usd, allow_partial_paid_sweep,
            max_age_days, remote_scopes, work_scope]}
SCORING = {"hard_drop_terms": [...]}          # from exclude_levels, as render()

TRACKS = [
    {
        "id": "a3f9c2e1b7d40c55",              # 8-32 lowercase hex; opaque
        "engine": "v2",                        # v1 | v2, explicit per track
        "SEARCH":   {"role_keywords": [...], "experience_years": 3},
        "SETTINGS": {"max_experience_years": 6, "candidate_experience_months": 40},
        "SCORING":  {"skill_weights": {...}, "penalty_terms": {...},
                     "frontend_terms": [...], "backend_terms": [...],
                     "fullstack_title_terms": [...], "fullstack_bonus": 0},
        "ATS_TITLE_HINTS": [...],
        "ATS_TITLE_EXCLUDE": [...],
    },
    ...
]
```

**Rules**

| Rule | Where |
|---|---|
| Stamp `{"version": 2, "engine": "multi"}`. Version 2 with any other engine, or `"multi"` on any other version, is refused. Versions ≥ 3 are refused as "newer build" | `profile_schema` |
| 1–3 tracks. Each track has **exactly** `TRACK_KEYS` and each section **exactly** its `TRACK_SECTIONS` keys: every key required, nothing else allowed. So no display name, filename or Sweep key can sit in a track | `check_tracks` |
| Ids are unique and match `[0-9a-f]{8,32}`. Engine is `v1` or `v2`. Lists of strings; whole numbers; weight tables map strings to ints | `check_tracks` |
| The Sweep's `SEARCH`/`SETTINGS`/`SCORING` carry no track key, and there is no top-level `ATS_TITLE_HINTS`/`ATS_TITLE_EXCLUDE` | `check_sweep` |
| `TRACKS` in a non-schema-2 file is refused, so a résumé cannot be silently ignored | `check_loaded` |
| Both loaders enforce all of the above (`config.load_profile_module` exits; `make_profile.load_profile` raises) | `check_loaded` |
| **Old build**: at `b542285`, `profile_schema` refuses version 2 as "written by a newer build", and its `check_module` refuses the name `TRACKS`. Verified by loading that commit's `make_profile.py` | fail-closed on a stale worker |

**Not in schema 2 yet**
- `FEEDS`: the Himalayas query union across tracks is Phase 3's.
- Résumé prose (`field_summary`, `notes`) in the docstring, which cuts exposure on disk.
- Gate comments.

## D. Pristine Defaults

```python
BASE_SCORING = copy.deepcopy(SCORING)    # config.py, after every default, before `if PROFILE:`
```

- It captures only `SCORING`, the one section a track reads through.
- A track carries all of its own `SEARCH` and `SETTINGS` keys, so no default fills them.
- The Sweep's `hard_drop_terms` falls back to the pristine default when the file omits it.
- `config.SWEEP_SCORING` is the file's own Sweep `SCORING` literal, not the globals.
- `config.TRACKS` is a deep copy of the file's `TRACKS`.
- Nothing here copies the rest of the config module.
- Schema 1 is untouched: its overlay onto the globals runs exactly as before.

## E. `TrackContext`

```python
@dataclass(frozen=True)
class TrackContext:
    id: str                    # opaque
    role_keywords: tuple       # the track's search intent
    experience_years: int
    title_hints: tuple         # its own free-source title gate
    title_exclude: tuple
    scoring: ScoringContext    # the Phase-1 type
    engine -> scoring.engine   # property: one source of truth
```

It holds no display name, résumé text or credential. `scraper.TRACK_CONTEXTS` is built at import, in file order, and is `()` for every schema-1 profile.

## F. How Each `ScoringContext` Is Built

```python
scoring = {**config.BASE_SCORING, **sweep_scoring, **track["SCORING"]}
scoring_context(scoring, track["SETTINGS"], track["engine"])
```

This is the same one-level merge `config._overlay` gives a profile: pristine defaults, then the Sweep's own `SCORING`, then the track's own values.
- It never reads the live globals, the process engine, `skill_concepts.enabled()` or the bind.
- For a schema-2 load, `config.PROFILE_ENGINE` stays `None`, so nothing is bound for the process.

## J. R-9 Title-Gate Code Finding (code only; no production access)

- **Where it's read:**
  - `make_profile._title_gate` calls `title_gate.enabled()` (`SWEEP_CANDIDATE_TITLE_GATE`) in the **rendering** process, per render.
  - Inside it, `family_centrality.enabled()` (`SWEEP_FAMILY_CENTRALITY_GATE`) is a **second** render-time flag. The design named only the first.
  - Neither flag is read by the engine at run time.
- **What it changes:**
  - Off: hints are the derivation's `title_hints` ∪ config's `ATS_TITLE_HINTS` floor, minus excludes.
  - On: hints come from `title_gate.build`: grounded held-title fragments, admitted role-family vocabulary, candidate hints filtered by family, and a corroborated stated target. The legacy floor is used only as a recorded last fallback.
  - Excludes are the derivation's `title_exclude` either way.
- **Fields it needs from `derived`:** `title_hints`, `title_exclude`, `role_signals` (`employment_titles`, `titles`, `target_field`), `role_evidence` (`supports`, `title_families`, `stated_target`), and `role_keywords` (only under the centrality flag). The `role_evidence` helpers it calls (`family_of`, `_PLATFORM_RX`) read no flags.
- **Is the design's projection complete?** Yes. Design §M carries all five fields.
- **Track-specific?** Yes. The gate is built from each derivation alone, so schema 2 stores hints and excludes **per track**.
- **Parity:** `render_sweep` calls the same `_title_gate`, so under the same flags each track's gate equals `render()`'s. Tested with both flags off, the gate on, and gate plus centrality on, for the synthetic tracks and the three personas. A test also proves the gate-on path produces different hints.

## M. Risks and Known Gaps

1. **Globals in a schema-2 process are the defaults for track-level keys.** They are guarded at `main()` and `default_context()`, the funnels production reaches. A direct in-process call to `plan_for_site`/`build_search_plan`/`is_dev_title` in a schema-2 process would still read the defaults. Nothing in production does that; Phase 3 replaces these paths.
2. **`check_tracks` checks shape and type on load, not value ranges.** `render_sweep` range-checks through `_weights`/`_years` when building. A hand-edited schema-2 file with a weight of 99 would load, just as a hand-written schema-1 file does today.
3. **Schema 2 accepts one track**, as specified. The design reserves schema 2 for 2–3 tracks in the UI; Phase 5 decides.
4. **Render-time flags (R-9).** Both title-gate flags are read by whichever process renders. Parity holds under the same flags. Which host renders public Sweeps is Phase 0b/4 territory, unchanged here.
5. **No production caller writes schema 2.** `render_sweep` is reached only by tests. A newer worker reads schema 2; an older one refuses it (verified).
6. **`BASE_SCORING` is a deep copy, but mutable by convention.** A test asserts that construction never writes it.
